# Развёртывание

Документ для того, кто будет выкладывать платформу. Приложение к хостингу
не привязано: это обычное Next.js-приложение и обычный Postgres.

---

## ⚠️ Сначала — то, что нельзя пропустить

**Сид заводит демо-аккаунты с паролем `password123`.** Он написан для
разработки. Если запустить `npm run db:seed` на боевой базе и оставить как
есть, любой, кто откроет README, войдёт учителем и админом.

На продакшене выберите одно из двух:

- не запускать `db:seed` вообще — только `db:migrate`, а первого админа
  завести вручную (см. ниже);
- запустить сид и **сразу удалить демо-аккаунты**:

```sql
delete from app_user where email like '%@example.com';
```

Проверить, что их не осталось:

```sql
select email, role from app_user order by role, email;
```

## Что нужно

| | Версия | Зачем |
|---|---|---|
| Node.js | 20+ | сборка и запуск |
| PostgreSQL | 16+ | вся схема; используется `gen_random_uuid()` из `pgcrypto` |

Нативных зависимостей нет намеренно: пароли на `scrypt` из `node:crypto`,
а не на `bcrypt`, поэтому приложение собирается на любом serverless-хостинге.

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `DATABASE_URL` | да | `postgres://user:pass@host:5432/db` |
| `ANTHROPIC_API_KEY` | нет | включает ИИ-помощника. Без неё платформа работает полностью, выключаются только панели разбора |

Больше ничего не требуется.

## Порядок выкладки

```bash
npm ci
npm run db:migrate     # применяет db/migrations/*.sql по порядку
npm run build
npm start              # слушает 3100; порт меняется в package.json
```

Миграции идемпотентны: применённое запоминается в таблице
`schema_migration`, повторный запуск ничего не ломает.

### Первый администратор без сида

```sql
-- 1. Зарегистрируйтесь через /signup обычным способом
-- 2. Повысьте себя до админа:
update app_user set role = 'admin' where email = 'вашапочта@пример.рф';
```

Дальше роли выдаются через `/admin` в интерфейсе. Последнего администратора
разжаловать нельзя — это правило в коде, а не соглашение.

### Проверка после выкладки

```bash
npm run check:invariants
```

Гоняет весь банк через ту же функцию, что блокирует публикацию, и собирает
весь LaTeX тем же кодом, что рендерит страницы. Должно закончиться строкой
`✓ банк валиден`.

## Варианты хостинга

### Vercel + управляемый Postgres (Neon, Supabase, RDS)

Самый короткий путь. Приложение собирается без изменений.

- `DATABASE_URL` — в переменные окружения проекта;
- миграции запускать из CI или локально против боевой базы: на Vercel нет
  шага, куда их естественно повесить;
- **пул соединений.** У serverless на каждый холодный старт своё соединение,
  и managed-Postgres кончается быстрее, чем кажется. Берите строку
  подключения через pooler (у Neon и Supabase он есть из коробки), а не
  прямую;
- чат: SSE-поток закрывается сам через 4 минуты и переподключается —
  это сделано специально под потолок serverless-функций, ничего настраивать
  не нужно.

### VPS + Docker

`docker-compose.yml` в репозитории поднимает только Postgres — он написан
для разработки. Для боевого сервера:

- Postgres из compose годится, но **обязательно смените пароль** `fm:fm`
  и не публикуйте порт 5439 наружу;
- приложение — под systemd или в своём контейнере, за nginx;
- в nginx для SSE выключите буферизацию, иначе чат будет приходить пачками:

```nginx
location /api/chat/ {
    proxy_pass http://127.0.0.1:3100;
    proxy_buffering off;
    proxy_read_timeout 5m;
}
```

Приложение и так шлёт `X-Accel-Buffering: no`, но явная настройка надёжнее.

## Безопасность перед публикацией

- [ ] демо-аккаунты `@example.com` удалены;
- [ ] пароль Postgres не `fm`;
- [ ] сайт за HTTPS. Кука сессии ставится с `httpOnly` и `sameSite`,
      но флаг `secure` имеет смысл только по HTTPS;
- [ ] `DATABASE_URL` и `ANTHROPIC_API_KEY` — в переменных окружения
      хостинга, не в репозитории. `.env.local` в `.gitignore`;
- [ ] порт базы не смотрит в интернет;
- [ ] бэкап базы настроен. В ней лежат попытки учеников — это то, что
      восстановить неоткуда.

## Что уже сделано на стороне кода

Перечислено, чтобы не искать заново:

- пароли — `scrypt`, в базе только хеш;
- сессии — в базе только `sha256` от токена: дамп базы не даёт войти
  под чужим аккаунтом;
- ссылки на видео разбираются на провайдера и идентификатор, в `iframe`
  уходит адрес, собранный кодом, — произвольный URL туда не попадает;
- ответ ИИ рендерится текстом, а не HTML;
- ключи ответов не уезжают в HTML страницы задачи — это проверяется
  в `npm run demo:walkthrough`;
- чужой класс, чужая попытка и чужой урок не «пустые», а отсутствующие:
  их существование наружу не подтверждается.

## Обновление

```bash
git pull
npm ci
npm run db:migrate
npm run build
# перезапустить процесс
```

Миграции только добавляют. Опубликованные версии задач неизменяемы
на уровне триггеров, поэтому откат приложения на предыдущую версию
не портит уже выставленные баллы.
