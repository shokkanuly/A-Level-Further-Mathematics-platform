# Математическая платформа

Четыре программы в одном банке задач: SAT, школьная математика, A-Level
Mathematics и A-Level Further Mathematics. Задачи в формате экзаменационного
билета со схемой оценивания по баллам, разборы на русском, уроки с видео
и конспектом, домашка с журналом и личный кабинет с мониторингом.

Целевая архитектура — в `files/SYSTEM-DESIGN.md`, ссылки на её разделы (§)
расставлены прямо в коде и в миграциях. Планы Stage 2–4 —
в `files/ARCHITECTURE-STAGES-2-4.md`. Выкладка — в [DEPLOY.md](DEPLOY.md).

## Запуск

```bash
npm install && cp .env.example .env.local && npm run db:up && npm run db:reset && npm run dev
```

Приложение — на `http://localhost:3100`, Postgres — на `5439` (порты 5432–5436
на этой машине заняты другими проектами; меняются в `docker-compose.yml` и `.env.local`).

Демо-вход (пароль у всех `password123`):

| Роль | Почта |
|---|---|
| Администратор | `admin@example.com` |
| Автор | `author@example.com` |
| Учитель | `teacher@example.com` |
| Ученик | `student@example.com` |

Эти аккаунты — для разработки. Перед публикацией их надо удалить: см. первый
раздел [DEPLOY.md](DEPLOY.md).

## Проверка

```bash
npm run check:invariants
```

Прогоняет банк через ту же функцию, что блокирует публикацию, и собирает
весь LaTeX тем же кодом, что рендерит страницу — под каждым достижимым
профилем обозначений отдельно.

```bash
npm run demo:classroom
```

Учебный цикл целиком: учитель входит, создаёт класс, ученик вступает по коду,
учитель выдаёт домашку, ученик решает, учитель видит журнал. Отдельно проверяет,
что чужой класс и чужая попытка недоступны, и главное правило разбора: одна
и та же задача в домашке и в свободной практике — две разные попытки,
и открытый разбор в практике не разблокирует домашку.

```bash
npm run demo:walkthrough
```

Сквозной прогон по HTTP: создаёт попытку, отвечает на все пять оцениваемых
частей смесью верного и неверного, забирает разбор и проверяет, что ключи
ответов не уехали в HTML. Ожидаемый итог — 4 из 8.

```bash
npm run demo:regrade
```

Автор занёс в ключ `BA` вместо `AB`, ученик ответил верно и получил ноль.
Скрипт публикует версию 2 с исправленным ключом и переигрывает сохранённый
ответ: 0 → 2 балла, с записью в журнале пересчётов.

## Решения, на которых всё держится

**Программа — данные, а не код** (`008_programs_and_kinds.sql`). Программа
встаёт над квалификацией, а не вместо комиссии: A-Level Further Maths держит
Edexcel 9FM0 и CIE 9231 одновременно, а комиссия по-прежнему отвечает только
за обозначения. Пятая программа добавляется строкой в `program`.

**Две таксономии** (`001_taxonomy.sql`). Концепты board-agnostic, пункты
спецификаций board-specific, между ними many-to-many. Задача привязана
к концептам и не знает про программы; список для SAT собирается обратным
обходом. Поэтому одно линейное уравнение стоит и в SAT, и в школьном блоке —
под разными номерами пунктов и **в одном экземпляре в банке**.

**Вид задачи — вторая, независимая ось.** Теория, практикум, экзаменационная,
олимпиадная. Обязательность разбора зависит от вида и лежит в таблице
`item_kind`, а не в форме автора: в форме это правило разошлось бы
с YAML-импортом и API, а разойдясь — тихо пропустило бы задачу без разбора.

**Блокирующая валидация** (`004`, `008`). `item_version_publish` не пропустит
версию, где сумма баллов расходится с заявленной, где схема оценивания
недобирает баллы, где нет концепта или где вид требует разбора, а разбора нет.
Триггеры не дают править опубликованную версию и менять её вид. Правило живёт
в базе: и форма автора, и будущий YAML-импорт проходят через одну проверку.
Форма автора умеет только показать заранее то, что всё равно скажет SQL.

**Задача как версионируемый документ** (`002_items.sql`). Части принадлежат
версии, а не задаче — поэтому `part_id` сам по себе несёт версию, и попытка
ученика намертво связана с тем, что он видел.

**Сырой ответ рядом с версией проверяльщика** (`003_attempts.sql`).
В `part_response` лежит то, что ввёл ученик, `graded_against_part_id`
указывает на часть, чьим ключом это проверили, а `marks_awarded` —
генерируемый столбец `coalesce(override_marks, auto_marks_awarded)`:
учительская правка и машинный балл хранятся раздельно.

**Разбор закрывается на сервере.** `GET /api/items/{slug}/solution` принимает
`attempt_id` и решает по контексту попытки. Без контекста ответить нельзя:
одна задача бывает одновременно в домашке и в свободной практике.

**Мониторинг считается по концептам и по последней попытке.** Ученик,
перешедший со школьного блока на A-Level, не теряет статистику. Точность —
по сумме баллов, а не по доле верных задач: 6 из 8 это не «неверно».
В списке «к кому подойти» не начатое задание и низкая точность не сложены
в один балл — «не открывал» и «не понял» лечатся по-разному.

**Чат привязан к классу.** Комнат ровно столько, сколько классов, плюс одна
общая; создавать произвольные нельзя — именно этим чат отличается от форума,
который `files/ROADMAP.md` запрещает. Транспорт — SSE, а не WebSocket, чтобы
не предрешать хостинг: WebSocket требует процесса, живущего между запросами,
которого на serverless нет.

**Видео хранится не ссылкой.** В базе — провайдер и идентификатор ролика,
адрес для `iframe` собирает `src/lib/video.ts`. Произвольный URL из формы
в `src` — это чужой скрипт в нашем origin.

**ИИ-помощник — надстройка.** Без `ANTHROPIC_API_KEY` панели выключены,
всё остальное работает. Модель отвечает по данным из `part_response`,
а не по общему знанию математики; имена учеников наружу не передаются.

## Чего здесь нет

CAS на SymPy и типов `symbolic` / `complex` (Stage 4), YAML-импорта задач,
загрузки фото решения. Из типов ответов работают `mcq`, `matrix` и `numeric` —
остальные возвращают `UNSUPPORTED_ANSWER_TYPE` явно, а не молчаливый ноль.
`regrade` написан как функция, а не как задача pg-boss.

## Раскладка

```
db/migrations/     SQL, применяется по порядку; схема читается отсюда
db/seed.mjs        программы, таксономии, пользователи, класс, урок
db/seed-items.mjs  помощник createItem: задача одним объектом
db/seed-bank.mjs   сам банк — по задаче на каждый вид
src/lib/grade.mjs  грейдеры; plain-JS, общий для API и скрипта пересчёта
src/lib/tex.mjs    KaTeX на сервере: renderTex для условий, renderRich для разборов
src/lib/programs.ts    витрина и фасетный фильтр
src/lib/cabinet.ts     мониторинг ученика и учителя
src/lib/community.ts   объявления, события, чат
src/lib/lessons.ts     уроки и просмотры
src/lib/video.ts       разбор ссылки на видео
src/lib/ai.ts          помощник за флагом ANTHROPIC_API_KEY
src/lib/solution-gate.ts   правило показа разбора
scripts/           валидатор банка и три демонстрационных прогона
```

`grade.mjs` и `tex.mjs` намеренно plain-JS: их импортируют и Next, и скрипты
на голом node. Грейдер, который «похож» на боевой, однажды разойдётся с ним
и пересчёт выставит не те баллы. По той же причине авторский конвейер ведёт
в базу через тот же `createItem`, которым засеян весь банк.
